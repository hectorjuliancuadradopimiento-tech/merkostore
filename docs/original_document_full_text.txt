1.1 Descripción del problema
Las tiendas de barrio cumplen una función importante en el comercio cotidiano,
pues ofrecen alimentos, bebidas, artículos
de aseo y otros productos de consumo fre-
cuente. Sin embargo, algunos pequeños comercios tienen dificultades para organizar el
catálogo, mantener actualizadas las existencias, registrar los pedidos y consultar sus
ventas. Cuando estos procesos se manejan de
forma manual o mediante herramientas se-
paradas, pueden presentarse errores en la disponibilidad de los productos, demoras al
atender solicitudes y dificultades para conocer el comportamiento de las ventas.
Merkostore surge como una solución tecnológica
para una tienda de barrio que busca
ofrecer sus productos por internet y facilitar las tareas del administrador. El sistema
cuenta con una vista pública para que los clientes consulten el catálogo, seleccionen
productos, gestionen su carrito y realicen ped

tionar productos, categorías, pedidos, usuarios y configuración de la tienda. La aplica-
ción utiliza tecnologías web y una base de datos para centralizar la información y man-
tener una relación más ordenada entre las v
entas y el inventario.
A pesar de contar con funcionalidades para administrar productos y pedidos, existe una
oportunidad de fortalecer el apoyo a las decisiones del negocio mediante el análisis de
las ventas, los niveles de existencias y la rentabilidad d

kostore puede servir como base para incorporar herramientas de Investigación de Ope-

4. Resultados
La
revisión funcional de Merkostore permite identificar una solución organizada
en dos áreas principales: la tienda pública para los clientes y el panel de administración
para el dueño del negocio. La tienda pública ofrece consulta de categorías y productos,
búsqueda, descuentos, carrito de compras, captura de datos de entrega y selección de
método de pago. El panel administrativo permite gestionar productos y categorías, revi-
sar indicadores de ventas, consultar pedidos, cambiar sus estados y administrar parám
e-
tros generales de la tienda.
En la lógica del backend se incluyen mecanismos para proteger la consistencia
de los pedidos y las existencias. La creación de pedidos valida los precios desde el ser-
vidor y descuenta stock mediante una operación atómica que c
omprueba que haya uni-
dades suficientes. Si el proceso falla, se contempla la reversión de las cantidades des-
contadas; cuando un pedido se cancela, el inventario asociado se restablece. También se
usa una clave de idempotencia para reducir el riesgo de regi
strar pedidos duplicados por
reintentos.
