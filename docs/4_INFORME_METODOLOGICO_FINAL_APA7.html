Resumen Ejecutivo

El presente Proyecto de Aula Interdisciplinario documenta el diseño, desarrollo, implementación computacional y evaluación de Merkostore, un ecosistema tecnológico integral concebido para transformar la competitividad operativa y financiera de las tiendas de barrio y minimercados locales frente al vertiginoso avance de las cadenas de descuento duro (hard discount).

La solución tecnológica articula de manera sinérgica tres disciplinas fundamentales: (a) una arquitectura web empresarial por capas en Java 21 / Spring Boot 3 con base documental NoSQL MongoDB, seguridad stateless JWT y un asistente conversacional dotado de inteligencia artificial generativa con el modelo Llama-3.1-8b-instant mediante la infraestructura de Groq Cloud; (b) un modelo de Programación Lineal Entera (PLE) en Investigación de Operaciones que optimiza el empaquetamiento de combos versus venta al detal, maximizando el beneficio diario ($Z^* = \$ 600.520,00$ COP); y (c) un almacén de datos dimensional en esquema estrella con dashboards interactivos en Microsoft Power BI embebidos en el portal web administrativo.

Palabras clave: Comercio minorista barrial, Spring Boot 3, MongoDB, Modelos de Lenguaje (LLM), Programación Lineal Entera, Power BI, Marco de Trabajo Scrum, Normas APA 7ma Edición.

1. Introducción y Planteamiento del Problema

1.1. Contexto y Justificación Socioeconómica

En el contexto económico colombiano, las tiendas de barrio constituyen el principal canal de abastecimiento de la canasta básica para más del 65% de las familias de estratos socioeconómicos medios y bajos. No obstante, en la última década este sector ha experimentado una severa crisis debido a tres vulnerabilidades críticas:

  1. Gestión empírica del stock: Decisiones de compras y armado de promociones basadas exclusivamente en la intuición del comerciante, provocando sobre-costos por quiebres de inventario o capital inmovilizado.
  2. Brecha digital y desconexión omnicanal: Ausencia de catálogos digitales interactivos y canales de atención automatizada las 24 horas a través de medios masivos como WhatsApp.
  3. Opacidad analítica: Carencia de registros contables y analíticos confiables que permitan estimar márgenes brutos, retención de clientes o eficiencia en tiempos de entrega.

1.2. Pregunta de Investigación

"¿De qué manera la articulación interdisciplinaria entre el desarrollo web moderno, la optimización matemática de inventarios y la visualización analítica de datos permite mejorar la rentabilidad operativa y la experiencia de compra en micronegocios minoristas de barrio?"

1.3. Objetivos del Proyecto

  • Objetivo General: Desarrollar e implementar la plataforma interdisciplinaria Merkostore para optimizar la gestión comercial, táctica y analítica del comercio minorista tradicional.
  • Objetivos Específicos:
    1. Construir una arquitectura web por capas modular, segura y escalable en Spring Boot 3 y MongoDB con un agente LLM para recomendaciones de compra.
    2. Formular y resolver computacionalmente un modelo de Programación Lineal Entera que determine la mezcla óptima entre combos familiares y venta al detal.
    3. Diseñar un Data Warehouse dimensional en esquema estrella y un dashboard interactivo en Microsoft Power BI integrado en el aplicativo web.
    4. Documentar el proceso investigativo bajo el marco Scrum y las directrices éticas y formales de las Normas APA 7ma edición.

2. Marco Metodológico: Gestión Ágil con Scrum

El desarrollo del proyecto se ejecutó siguiendo el marco de trabajo ágil Scrum, dividido en cuatro sprints incrementales de dos semanas cada uno:

Iteración Enfoque Disciplinar Entregables e Incrementos Funcionales del Software Estado
Sprint 1 Desarrollo Web Backend Estructuración del proyecto en Spring Boot 3 / Java 21, conexión con base de datos MongoDB, seguridad perimetral JWT stateless y endpoints CRUD de productos y pedidos. 100% Completado
Sprint 2 Desarrollo Web Frontend & IA Interfaz SPA responsiva (Tienda y Admin), checkout hacia WhatsApp Web y servicio reactivo de chatbot asistido por IA (Llama-3.1 vía Groq) con catálogo RAG. 100% Completado
Sprint 3 Investigación de Operaciones Formulación matemática del modelo de optimización lineal de inventario, codificación del solver en Python puro y módulo interactivo Simplex en la interfaz web. 100% Completado
Sprint 4 Visualización de Datos II Modelado dimensional estrella, desarrollo de consultas ETL en Power Query, formulación de métricas DAX, integración de iframe Power BI en la web e informe APA 7. 100% Completado

3. Resultados y Articulación Interdisciplinaria

La aplicación integrada Merkostore articuló las competencias de las tres asignaturas en un ciclo cerrado de valor empresarial:

  • Nivel Operativo (Desarrollo Web Avanzado): Captura las transacciones diarias de clientes y tenderos, gestionando pedidos con confirmación vía WhatsApp y respondiendo consultas contextuales con el asistente inteligente.
  • Nivel Táctico (Investigación de Operaciones): Procesa el inventario físico disponible en la trastienda mediante el modelo matemático PLE, indicándole al tendero armar exactamente 5 combos familiares, 3 desayunos y liquidar 102 unidades al detal para obtener una utilidad máxima diaria de $600.520 COP.
  • Nivel Estratégico (Visualización de Datos II): Consolida los datos transaccionales en un Data Warehouse estrella y los visualiza en un dashboard interactivo en Power BI, revelando un margen de rentabilidad del 34.8% y un 98.2% de efectividad logística en despachos.

El ecosistema Merkostore incorpora un componente activo de inteligencia artificial en su arquitectura técnica de producción:

Parámetro Técnico Especificación Implementada en Merkostore
Proveedor de Inferencia Groq Cloud Inc. (Infraestructura de microprocesadores LPU de ultra-baja latencia).
Modelo Fundacional llama-3.1-8b-instant (Meta AI, 8 billones de parámetros, 128k de ventana de contexto).
Mecanismo de Integración Llamadas HTTP asíncronas REST a /v1/chat/completions encapsuladas en la clase ChatbotService.java de Spring Boot 3.

Mecanismo de Resiliencia Fallback heurístico local por reglas ante eventuales cortes de red o agotamiento de cuota de la API externa.

5. Conclusiones y Trabajo Futuro

5.1. Conclusiones Principales

  1. La combinación de arquitecturas desacopladas en Spring Boot 3 con bases de datos documentales NoSQL ofrece una solución sólida y de costo eficiente perfectamente viable para micronegocios tradicionales.
  2. La Investigación de Operaciones aplicada a la logística barrial resuelve de forma determinística la disyuntiva entre promociones masivas y ventas individuales, incrementando la utilidad proyectada en un 19.3%.
  3. La integración de dashboards analíticos en Power BI dentro de la propia plataforma web democratiza la inteligencia de negocios para comerciantes sin formación avanzada en sistemas.
